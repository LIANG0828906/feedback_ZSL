# MeshForge 技术说明

## 1. 设计边界

MeshForge 是单机、纯标准库、确定性的三角网格修复工作台。Go 标准库没有跨平台原生桌面 GUI，因此界面采用任务允许的本地 Web 方案：`net/http` 只监听回环地址，HTML/CSS/Canvas JS 全部内联，不引用 CDN、字体或第三方脚本。

持久化只使用工作目录中的 JSON 文件。没有数据库、容器、网络下载或后台服务。

## 2. 网格内核

`internal/mesh` 负责：

- `Vec3`、`Face`、`Mesh` 数据类型；
- 规范内容哈希：顶点/面数量、IEEE-754 位模式、面索引按固定字节序写入 SHA-256；
- 无向边记录与边使用方向；
- 边界图、闭合环顺序和开放链统计；
- 面连通分量；
- 法向奇偶约束求解与闭合体积定向；
- 三角形 AABB BVH 与非邻接三角形精确相交检测；
- 原子文件写入：同目录临时文件、`fsync`、`rename`、目录 `fsync`。

所有依赖 map 迭代的算法都会先排序，避免 Go map 随机顺序影响结果。平滑邻接表也必须排序，否则浮点求和顺序会造成最终哈希差异。

## 3. 确定性样本生成

基线为八面体重复四分细分并投影到单位球：

```text
V(L) = 2 + 4^(L+1)
F(L) = 8 * 4^L
E(L) = 12 * 4^L
χ = 2
```

生成器使用自实现 xorshift64* 伪随机数，不依赖标准库随机实现细节。固定参数下产生：

1. 高频径向噪声，供去噪向真值位置收敛；
2. 两个不相邻三角孔；
3. 5 个互不共享顶点、且避开孔洞的翻转面；
4. 若干精确重复顶点，并把部分关联面角点重映射到副本；
5. 一个共边附着三角片，使该边成为三面非流形边；
6. 一个跨越球面的平坦双三角薄片，产生可测的三角形对相交。

真值清单在生成后由独立诊断路径计算，并保存输入面数、原始/修复后拓扑、已知点、孔洞环、缺陷面编号和诊断期望。测试会把加载后的诊断结果与清单逐项比对。

## 4. 诊断

诊断顺序：

1. 面数是否等于清单 `input_faces`；
2. 每个面索引是否在 `[0, V)`；
3. 是否重复索引或面积为零/非有限；
4. 构建拓扑并统计非流形边、精确重复顶点、边界环/开放链、连通分量、薄片分量和相交对；
5. 用边方向奇偶约束统计翻转面与朝向冲突边；
6. 与真值清单逐项比较。

索引、退化面和面数错误返回 `E_GEOM`，并设置 `face_index`。面数不足时，首个违规编号为已有面数；面数过多时，首个违规编号为清单声明面数。

## 5. 焊接与规范化

焊接容差为 `tol`：

- `tol == 0`：按浮点位模式精确合并；
- `tol > 0`：以 `tol` 为格宽建立空间哈希，每个顶点只检查 3×3×3 邻格，再做并查集合并。

代表点选择簇内最小原始索引，顶点按原索引升序压缩。这样生成样本的基线顶点索引在焊接后保持稳定，已知点索引可直接复用。

若合并后面出现重复索引或零面积，返回 `E_TOLO`，并给出原网格最短有效边长 1/4 的建议容差。

规范化步骤：

1. 删除相同顶点集合的重复面；
2. 对每条非流形边，计算候选面的边界边数量，优先删除附着片候选，循环直到无三面以上边；
3. 删除面数小于主分量 5% 且开放的小型辅助分量；
4. 压缩未使用顶点；
5. 检查边界环是否退化。

该策略面向样本中的附着片和穿透薄片；阈值通过 `min-component-pct` 可配置。

## 6. 孔洞填补

边界分析只把每条边恰好一个使用面的边视为边界。边界子图按连通分量检查：

- 每个顶点度数为 2 且边数等于顶点数：闭合环；
- 否则：开放链。

开放链或少于 3 个顶点的环返回 `E_TOLO`。

对每个闭合环：

- Newell 法向和最大投影轴用于降维；
- 有向面积和逐角叉积判断凸性；
- 凸环默认从环首点扇形三角化；
- 非凸环使用确定性耳切；
- 输出绕序取边界环反向，使新增面与相邻面绕序一致；
- 记录环的凸性、三角化方法、法向连续性和新增面积。

填补后重新构建拓扑，要求边界环和开放链均为 0，且非流形边数不增加；否则返回 `E_TOLO` 并给出更小容差建议。

## 7. 定向

对每条恰好两个使用面的边：

- 两面沿该边的方向相反：奇偶约束为相同；
- 方向相同：后继面需要反转，奇偶约束取反。

非流形边不参与传播。每个连通分量 BFS 求解奇偶，随后：

- 显著分量或闭合分量按有符号体积调整全局符号；
- 微型开放分量只按根面求解局部一致性，避免薄片自身造成虚假“翻转面”统计。

出现奇偶矛盾或求解后仍有冲突边时返回 `E_ORIENT`，列出分量编号。

## 8. 去噪

去噪采用 Taubin 两遍拉普拉斯：

```text
lambda = configured weight, (0, 0.75]
mu     = -lambda / (1 - 0.1*lambda)
每次迭代：v ← v + lambda*(avg(neighbors)-v)
          v ← v + mu    *(avg(neighbors)-v)
```

拉普拉斯邻接表排序后求和。权重或迭代次数越界返回 `E_PARA`。去噪只改顶点位置，并显式比较去噪前后面列表、V/F/E/χ；同时用清单已知点的平均位置误差验证收敛。

默认样本的噪声为高频径向扰动，Taubin 正负两遍在抑制噪声的同时保持整体体积。

## 9. 自适应模式

配置包含：

- `fine_face_limit`
- `fine_component_limit`
- `time_budget_ms`
- `memory_budget_mb`
- `chunk_target_faces`
- `max_parallel`
- `per_worker_buffer_mb`

候选估算：

```text
exact_time   = faces*0.045ms + components*2.0ms
exact_mem    = faces*1600B + 8MiB
spatial_time = faces*0.038ms + components*1.5ms
spatial_mem  = faces*2200B + 8MiB
```

自动规则：

1. 精细可行要求面数、分量、时间、内存全部满足；
2. 分块可行要求时间、内存满足；
3. 两者都可行选精细；
4. 精细不可行、分块可行选分块；
5. 都不可行返回 `E_SCALE`。

显式 `exact`/`spatial` 模式用于验收对照，仍受时间和内存预算约束。

分块网格：

```text
grid = ceil(cuberoot(faces / chunk_target_faces))
edge = bbox_diagonal / grid
```

若每块估算面数超过 `per_worker_buffer_mb` 换算的 face 上限，则增加 grid 直到满足。每个阶段可对分块执行确定性 worker pool 探测，任务结果按块号合并，记录块数、块面数、worker 上限和摘要哈希。

空间修复路径为分块 broad phase + 跨块精确 narrow phase。它对块内候选批次并行处理，但邻接、焊接、填补和定向判定仍使用精确谓词，因此输出拓扑与精细路径一致。

## 10. 质量一致性

`RunConsistency` 在同一输入上分别强制精细和空间模式运行全部六阶段，比较：

- 顶点数；
- 面数；
- 欧拉特征数；
- 孔洞填补面积。

前三项容差为 0，填补面积容差为 `max(1e-9, |fine_area|*1e-6)`。任一项超差返回 `E_SCALE`，错误对象包含：

- `item`：超差项名称；
- `left`：精细模式实测值；
- `right`：分块模式实测值；
- `tolerance`：声明容差。

报告同时包含两模式的墙钟耗时、Go 堆峰值采样、总分配字节、并行度和 worker 缓冲预算。拓扑/面积结果生成确定性 `quality_fingerprint`；耗时和堆采样属于运行观测字段，不参与指纹。

## 11. 状态机

阶段固定为：

```text
diagnose, weld, fill, orient, denoise, stats
```

合法迁移：

```text
pending    -> processing
processing -> committed
processing -> failed
failed     -> processing
```

`committed` 是冻结终态。全量运行只推进尚未提交的阶段；非法迁移返回 `E_STATE` 且不修改原状态。失败阶段只能通过 `Retry` 重新进入 `processing`。

参数修改有提交边界：

- 焊接已提交后拒绝修改焊接参数；
- 去噪或统计已提交后拒绝修改平滑参数；
- 修改未提交参数会生成新的参数版本；旧快照有意保留旧版本，因此下次重启会按版本不匹配整体作废。

## 12. 检查点

`manifest.json` 保存：

```text
format, run_id, input_hash, parameter_version, algorithm_version
commits[{stage_index, stage, file, mesh_hash, parent_hash}]
```

每阶段快照保存：

```text
stage_index, stage, parent_hash, mesh_hash,
input_hash, parameter_version, algorithm_version,
mesh{document}, stages[6]
```

提交过程：

1. 阶段结果进入内存；
2. 在互斥锁内构造快照；
3. 原子写阶段文件；
4. 更新 manifest 并原子写入。

`CheckpointStore` 的互斥锁和 Pipeline 的顺序操作锁保证写入不交错、提交序列稳定。

恢复过程逐阶段读取所有快照：

- 检查 manifest 版本；
- 检查阶段序号连续；
- 检查 `parent_hash` 链；
- 重新计算快照网格内容哈希；
- 检查快照和 manifest 的网格哈希一致；
- 检查快照阶段矩阵前缀均为 committed。

任何异常返回无效原因，Pipeline 调用 `Invalidate` 清理 manifest 和阶段文件，再从 `pending` 全量计算。

## 13. 并发和资源边界

- `MaxParallel` 决定 worker 上限；
- `WorkerPool` 同时接受 `MaxFacesPerTask`；
- 每个分块任务超过 face 上限会被拒绝；
- 共享检查点写入由 `CheckpointStore.mu` 串行化；
- 阶段提交在 Pipeline 操作锁内按固定顺序进行；
- 分块任务输出按块索引写回切片，不依赖完成顺序；
- 平滑邻接、边和碰撞结果都确定性排序。

验收测试对空间模式使用 `MaxParallel=1` 和 `MaxParallel>=2` 各跑一次，比较最终内容哈希、每阶段内容哈希和拓扑。

## 14. Web 与可视化

HTTP 端点：

```text
GET  /                  内联 HTML/JS
GET  /api/state         状态机、决策、真值、曲线
GET  /api/mesh          original | repaired | stage=<name>
POST /api/run           运行/续跑
POST /api/retry         重试失败阶段并继续
```

Canvas 渲染对超过 22,000 个面的查看请求做确定性 stride 显示，但 API 返回完整网格；高亮面总会被绘制。剖面通过模型 Z 轴对每个三角形做 Sutherland-Hodgman 平面裁剪。所有解析与修复结果不依赖浏览器。

## 15. 已知限制与取舍

- 自动删片策略针对本任务生成的辅助薄片和附着片；真正的多材质、多封闭组件生产资产需要扩展“辅助分量”判定。
- 去噪是 Taubin 全局拉普拉斯，不包含保特征/双边滤波；样本已知点验证表明误差下降，但生产资产可继续替换为特征保持平滑。
- 峰值内存是 Go `HeapAlloc` 的 2ms 采样峰值，不是操作系统 RSS。
- 分块路径当前使用精确 narrow phase，因此质量与精细路径一致，不以拓扑误差换取速度；大规模性能收益主要来自并发和缓存局部性。
- Web 查看器是轻量诊断视图，不是完整 DCC 渲染器。
