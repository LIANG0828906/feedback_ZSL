# EdgeForge 技术说明

## 1. 模块划分

| 模块 | 职责 |
| --- | --- |
| `edgeforge/samples.py` | 固定种子样本、真值掩膜、端点/圆参数和 manifest |
| `edgeforge/image_io.py` | PNG 头解析、QImage 编解码、数组格式转换 |
| `edgeforge/loader.py` | 尺寸/通道/真值/哈希校验及无状态加载 |
| `edgeforge/algorithms.py` | 梯度、双阈值、开闭、细化、剪枝 |
| `edgeforge/config.py` | 参数校验、版本哈希、边带联动公式 |
| `edgeforge/blocks.py` | 固定核心块与扩展边带区域 |
| `edgeforge/stages.py` | 阶段枚举、四态状态机、进度快照 |
| `edgeforge/resource.py` | 暂停/取消控制与全局内存预算 |

## 2. 确定性算法

### 梯度

3×3 算子先在边缘复制填充的图像上计算 `gx/gy`，再按算子理论最大幅值归一化到 `[0,255]`，输出 `float32`。单通道输入输出二维数组，三通道输入逐通道输出三维数组。全程只有逐元素运算，没有依赖线程数的归约。

### 双阈值

`strong = magnitude >= high`，`weak = magnitude >= low`。对强边缘做 3×3 方形膨胀得到 1 像素支持区，最终 `edge = weak & support(strong)`。该定义依赖半径固定为 1，既保留双阈值语义，又保持有限边带。

### 形态学

结构元素可选 `cross` 或 `square`，尺寸必须为 1..31 的奇数。二值膨胀取邻域逻辑或，腐蚀取邻域逻辑与；开运算为“腐蚀后膨胀”，闭运算为“膨胀后腐蚀”。由于开/闭各含两次半径 r 操作，核心输出最多依赖输入 2r 邻域。

### 细化

Zhang-Suen 两子迭代并行删除，邻域越界按背景处理。最多执行 `thin_iterations` 次；若一轮没有变化则提前结束。每次迭代影响半径 1，n 次迭代依赖输入 n 邻域，因此边带使用 `n+1` 保守上界。

### 短线段剪枝

按 8 连通分量统计像素数。分量大小不超过 `prune_length` 时删除。分块处理时，若分量触及“人为扩展边界”，说明它可能是跨块长分量的一部分，保留该分量；真实图像边界不视为人为边界。边长阈值 p 的分量在核心像素周围最多跨越 p 像素，因此边带使用 `p+1`。

## 3. 跨块一致性

对阶段 S，设核心块为 B，边带为 h，扩展区域为 `E = dilate(B,h)`。任务只在 E 上执行 S，然后裁回 B。由于 S 对任意核心像素的有限依赖半径不超过 h，E 外的像素不会影响 B 内结果；图像真实边界使用与整图相同的零/复制边界规则。由此：

```text
S_tiled(B) == S_whole(E)[B]
```

流水线按阶段屏障推进：前一阶段所有块提交并组装成完整数组后，下一阶段从完整数组读取扩展区域。这样每一阶段都可独立验证，不依赖块完成顺序。

整图参考路径 `process_whole_image` 使用相同阶段函数但一次性处理整图；串行分块、并行分块与整图路径在测试和验收中逐像素相等。

## 4. 调度与提交

并行调度器维护：

- 待调度块队列。
- 活动 `Future` 集合。
- 每任务预估扩展像素和字节数。
- 全局 `MemoryBudget` 预留量。
- 已完成但等待前序块的结果表。

调度循环只在 `active < max_parallel` 且预算预留成功时提交任务。若全局余额不足，则记录 `budget_queue` 事件并等待活动任务完成，不会跳过该块。若单个任务超过 `thread_buffer_pixels` 或大于整个全局预算，返回明确 `E_BUDGET`，避免无限等待。

任务完成顺序可能任意，但协调器按块号推进提交游标。只有当前应提交块的结果已到达时，才进行状态迁移和检查点写入，因此提交顺序稳定且不交错。失败块会进入 `failed` 并记录错误；同阶段其他块可继续提交。阶段末尾若存在失败，抛出 `E_PIPELINE`，后续阶段不推进。

## 5. 检查点协议

运行指纹由以下内容规范化 JSON 后 SHA-256 得到：

- 样本 ID、图像哈希、真值哈希、尺寸、通道。
- 分块尺寸。
- 参数版本（算子、阈值、结构元素、细化、剪枝，以及影响块布局的尺寸）。
- 算法版本。

并行度、内存预算等不改变输出，因此不参与参数版本；可在续跑时调整。

每条记录独立包含输出数组和全部验证字段，因此不依赖单独的可变日志。写入步骤：

1. 在记录目录创建唯一 `.tmp-*` 文件。
2. 写入 `npz`，`flush` 并 `fsync`。
3. `os.replace` 原子替换到最终文件名。
4. 在协调器内存中推进序号。

若第 2/3 步之间进程被杀，只剩临时文件，重启扫描会忽略；若第 3 步后被杀，完整记录已可恢复。

启动校验失败时，旧目录整体改名为 `*.invalid-<UTC>-<纳秒>`，新目录写入相同运行指纹，状态机清空并全量重算。旧目录不会自动删除，方便取证；`python -m edgeforge clean` 可清理 `runs`。

## 6. 三路径一致性与差异定位

`first_stage_difference` 按固定阶段顺序扫描数组：

1. 比较形状。
2. 逐像素比较，三通道使用任一通道不同即差异。
3. 用 `np.argmax` 定位行优先首差异。
4. 由坐标与 `tile_size` 计算块号。
5. 返回 `x/y/stage/block_id/reason`。

指标不缓存自某条路径，而是由组装后的最终掩膜重新计算，因此串行、并行、恢复和全量重算得到完全相同的统计字典。

## 7. 异常与恢复边界

- 解码失败、形状不符、参数非法在任务开始前或加载时立即失败。
- 单任务内部异常被转换为失败结果，不逃逸污染线程池中的其他块。
- 取消在调度循环和任务入口检查；已提交记录保留，未提交任务丢弃。
- 强制终止不执行清理协议，不承诺完整报告；重启只信任通过指纹和哈希校验的记录。
- 检查点目录仅含原子记录，不依赖“进程正常退出时补写索引”。

## 8. 验证口径

`python -m edgeforge verify` 使用 320×240 单通道样本与 800×600 三通道样本，64/128 像素分块。主验收检查：

- 串行 vs 并行全部六个阶段逐像素及指标相等。
- 整图单块 vs 分块全部阶段逐像素相等。
- 前三阶段完成后重启，恢复提交数与持久化数一致。
- 第 25 个块提交后主动取消，形成“部分已提交阶段”，重启后仍与基准逐像素相等。
- 篡改首条记录数组但不改哈希，启动时识别 `record_hash_mismatch` 并整体作废。
- 低预算下排队事件大于零、所有块最终提交、输出仍与基准一致。
- `E_DECODE/E_META/E_PARA/E_STATE/E_BAND/E_BUDGET` 全部实际触发。
