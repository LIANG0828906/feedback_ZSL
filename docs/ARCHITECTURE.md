# 架构与算法说明

## 1. 分层

- `pkg/tactical`：无 UI 的确定性领域核心。
- `pkg/workbench`：面向操作应用的会话服务，负责首次加载、恢复、编辑、暂停、重启和检查点保存。
- `desktop`：Wails 绑定与静态诊断前端。
- `internal/sample`：固定种子地图、编队、指令、解析真值。
- `cmd/verify`：不依赖 GUI 的端到端验收。

所有业务数据均可 JSON 序列化；核心不依赖本地服务、网络、账号或容器。

## 2. 坐标与定点约定

- 栅格坐标：整数 `(x,y)`。
- 固定点坐标：`q0.001` 格，`1000` 表示一格。
- 世界坐标：固定点除以 `1000`，仅作为诊断读数。
- 朝向：milliradian；满周 `6283`。
- 路径代价、启发式、移动步长均为整数；无浮点累加。

平滑、轨迹和重叠判定全部在固定点空间执行。轨迹点允许落在整数固定点栅格上，因此用不超过一个量化单位（`0.001` 格）的线段距离容差验证“位于折线上”。

## 3. 结构校验

`ParseScenario` 先按原始 JSON 对象逐层检查必需字段，再执行语义校验：

- 成员 ID 唯一，槽位 ID 唯一。
- 槽位 `dx/dy/tolerance` 有限；相对偏移和锚点起终点不得越界。
- 起终点在界内。
- 可通行格代价为正整数；不可通行格必须有 `blocked_by` 或显式不可通行地形。
- 指令按 tick 非降序且引用现有成员。
- 成员依赖无环。

失败统一返回 `*tactical.Error{Code: E_SCHEMA, Field: ...}`。

## 4. 成员分层搜索

每个成员独立执行整数代价 A*：

1. 先在同一有效地图上从终点做反向 Dijkstra，得到精确剩余代价表。
2. 默认启发式直接使用该表，因此不会高估；自定义启发式会逐格检查。
3. 权重以 `0..1000` 表示 `0..1.0`，并使用不溢出的整数缩放。
4. 四邻域/八邻域支持，八邻域禁止穿越不可通行拐角。
5. 优先级并列时用“到起终点直线的偏移”作稳定 tie-break，避免等权地图产生无意义锯齿路径。
6. 累加代价上限 `MaxPathCost = 2^60`；越界返回 `E_HEUR` 并携带成员。

同一场景、起终点、邻域与权重重复搜索得到逐格一致路径。

## 5. 协同平滑

- 使用固定点视线检测（Bresenham + 对角两侧格检查）。
- 以槽位容差作为几何 epsilon，执行确定性的最远视线捷径压缩。
- 容差收紧时只可能保留更多拐点，不会减少。
- 平滑不重新定价：`SmoothedPath.SourceCost` 保留原始最小代价，因此不会低于最小代价。
- 输出拐点同时包含网格坐标、固定点坐标和连续世界坐标。
- 按归一化路径进度检查槽位相对偏差与成员间最大间距；失败返回 `E_FORM`，携带成员对与当前距离。

## 6. 逐 tick 推演

状态机约束：

- 步长/转向速率越界返回 `E_PARA`。
- 到达拐点后不瞬转：后续 tick 最多旋转配置的转向速率，未完成转向前不移动。
- 每个 tick 只沿当前段前进，最多到达段终点，不跨段。
- 段内已走距离单独累计，位置从段起点重算，避免逐 tick 整数截断误差累积。
- 位置、朝向、段索引、队形偏差逐 tick 写入缓存。
- `ValidateTrace` 再检查 tick 连续、段单调不跳段、折线距离不超一个量化单位、单 tick 朝向变化不超限；失败返回 `E_TRACE`。

## 7. 依赖与失效传播

每个成员持久化：

- 原始路径格与平滑视线所经过的格集合。
- 地形分类集合。
- 封锁区域标识。
- 同组队形耦合成员。
- 逐 tick 推演区间与耦合区间。

编辑分类：

- 封锁/涨价：只失效实际经过该格的成员路径。
- 降价/解封：可能产生新的全局最优路径，除实际经过者外，将潜在候选成员纳入重算，以保证“增量 == 空缓存全量”。原因写入失效清单，避免静默使用旧最优解。

路径失效后，同组成员因队形偏差依赖而失效对应推演区间；其他小组路径与推演区间直接复用。

失效条目按场景成员顺序、区间、类型稳定排序，包含成员 ID、tick 区间和原因。

## 8. 增量提交与一致性

`Engine.ApplyCostEdit` / `Engine.ApplyRegionEdit`：

1. 在副本上计算新地图与失效清单。
2. 按拓扑序只重算失效路径。
3. 平滑后重新检查全局队形约束。
4. 仅重算失效推演区间，其他区间复用。
5. 重建依赖图。
6. 默认从空缓存执行全量重算，并用 `CompareSnapshots` 比较。
7. 全部一致后才原子替换内存快照；任何错误保持旧快照不变。

比较顺序固定为：地图/版本、成员顺序、路径格序列、路径累计代价、拐点序列、逐 tick 位置/朝向/段/队形偏差、队形统计。首个差异返回 `E_DIFF` 的 `member_id`、`tick`、`item`。

## 9. SQLite 检查点

表：

- `checkpoints`：单例快照元数据与完整 payload。
- `member_partitions`：按成员分区路径、拐点、轨迹与依赖。
- `commit_log`：稳定提交顺序审计。

写入规则：

- 进程内单写锁。
- 单 SQLite 事务写入全部成员分区。
- 成员行顺序严格等于 `Snapshot.MemberOrder`。
- 禁止交错提交，崩溃时事务整体回滚。

恢复规则：

地图内容哈希、槽位版本、定点参数版本、算法版本任意不匹配时删除整个检查点并返回 stale，绝不混用部分旧缓存；调用 `ResumeOrRebuild` 会从空缓存全量重算并重新写入。

## 10. 并发调度与资源边界

`WindowScheduler` 使用固定大小工作线程池：

- `MaxParallel` 限制 worker 数。
- `EngineOptions.MaxParallel > 1` 时，逐成员轨迹计算通过该调度器并行执行；轨迹合并后才做锚点队形偏差标注。
- `StateBuffer` 每 worker 硬上限，`Push` 满时阻塞并计数，不丢弃状态。
- worker 结果进入有界结果通道，满时阻塞。
- 单一协调器按窗口输入顺序执行 commit；全局决策合并与 SQLite 写入应只放在 commit 回调。
- 并行与串行运行产生相同输出与提交序列。

验收中的 6 个成员窗口在 4 路并行下峰值 4，提交顺序与串行完全一致。
