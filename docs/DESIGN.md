# 设计说明

## 1. 内部模型与不可变性

内部有向图模型统一为：

- 顶点：ID、分片 ID、声明序号、标签集合、属性表。
- 边：ID、源/目标顶点、方向、权重、可选层级标签、源分片、声明序号。
- 属性：整型、百万分定点、字符串三类。

装载时所有版本都归一到毫秒、字节和百万分定点：

- `tick` 乘以声明的毫秒/tick；
- `KiB` 乘以 1024；
- 千分/万分定点按预期 schema 刻度换算为百万分定点，转换不能有精度损失，否则返回 `E_BAD_ATTRIBUTE_SCALE`。

`engine.NewRuntime` 对传入工程做深拷贝；所有编辑先在工作副本上完成、验证、评估，成功后一次性替换运行时状态。因此任何异常都不会污染调用方工程或已经提交的运行时。

## 2. 三版装载与消歧

装载器先读取原始 JSON 对象，再执行：

1. schema 标记、字段线索和别名冲突检测；
2. 版本专用结构解码；
3. 顶点按标签、边按层级标签的嵌套树去重（同一实体可在多标签组重复出现，但声明必须完全一致）；
4. 属性刻度、时间/容量单位归一；
5. 分片区间校验与顶点/边归属求解。

无法消歧的组合包括：

- 多个 schema 标记指向不同版本；
- `project_id` / `projectId` / `dataset_id` 等别名同时存在且值不同；
- 同一文档同时以不同内容提供扁平顶点列表和嵌套标签树；
- v2 嵌套树同一顶点出现两次且字段内容冲突；
- 声明分片 ID 与实际键区间解析结果冲突。

可选层级字段缺失时，模型显式设置 `HierarchyEnabled=false`、`HierarchyDegraded=true`，并写入降级说明。层级别名和层级索引键随该标记关闭。核心一致性摘要不包含可选层级，因此三版 core digest 相同；v1/v2 之间仍额外比较层级内容。

## 3. 分片与索引键

分片键空间按 `[low, high)` 定义：

- 顶点归属由顶点 ID 求解；
- 边归属由源顶点 ID 求解；
- 区间重叠、反向/空区间、键落在空间外、边端点缺失均返回带上下文业务错误。

分片内实体顺序来自声明序号；相同声明序号时用 ID 打破平局，保证稳定。

索引键只依赖声明输入：

```text
v:vertex:<id>                      实体身份键
v:label:<label>                    标签键
v:int:<attr>:b<floorDiv(value,width)>
v:fixed:<attr>:b<floorDiv(micros,width)>
v:string:<attr>:p:<rune-prefix>
e:edge:<id>                        边身份键
e:out:<from>                       源邻接键
e:out:<from>:lvl:<level>           层级邻接键
```

键内片段用 URL query escaping，属性规则、标签集合、层级集合都排序后再生成。分片构建的局部 key 贡献按分片 ID 排序合并，索引键版本从 1 开始。

## 4. 遍历语义

每次查询先建立确定性邻接表：边按声明序号排序，同序号按边 ID 排序。BFS：

- 起始顶点先进入访问序列；
- 每层按当前 frontier 的发现顺序展开；
- 每个顶点的出边按声明顺序枚举，枚举过的边都进入访问边序列；
- 新发现顶点进入下一层和访问序列；
- `one_hop` / `two_hop` 的结果是深度上限内、满足全部标签条件的非起点顶点，按声明顺序输出；
- `shortest_path` 在首次发现满足标签的目标顶点时停止，保留父边并重建路径。

内核状态：

| 状态 | 含义 |
|---|---|
| `start_missing` | 起点不存在 |
| `depth_zero` | 起点存在但深度为 0 |
| `target_unreachable` | 目标在深度上限内不可达 |
| `ok` | 正常完成 |

索引布局只影响候选标签集合的获取方式。`index` 布局通过标签索引取候选，`scan` 布局扫描顶点；两者都用同一实际 BFS 与标签复核，因此访问序列和结果一致。

## 5. 缓存分层、引用与版本

- 索引层：`ShardIndex` 保存分片本地 key 贡献；`IndexKey` 保存全局 key 的引用分片集合、实体集合、版本。
- 缓存层：独立 `CacheStore`，缓存 ID 由逻辑查询规范串 SHA-1 前 12 位生成。
- 缓存依赖：标签探针键、访问顶点身份键、访问顶点分片、访问边身份键、访问边分片、展开顶点的邻接键。

编辑时：

1. 计算实体旧/新索引键；
2. 只增删发生变化的分片贡献；
3. 对受影响 key 的全局版本递增一次；
4. 若 key 仍被其他分片引用则保留；
5. 引用与实体集合都归零后才回收；
6. 用受影响 key、实体身份、重划分分片生成传播闭包；
7. 仅依赖闭包的缓存失效，其余缓存原样复用。

`OperationReport` 同时输出：

- 变更实体与传播闭包；
- 受影响 key 集合；
- 失效缓存、查询 ID 与命中原因；
- 复用/重建缓存编号；
- 当前全部索引键的引用分片、版本、实体和关联缓存编号；
- 当前分片状态及实际耗时观测值。

## 6. 增量编辑与重划分

顶点增删改、边增删改均在工作副本上完成：

- 顶点更新比较旧/新身份、标签、属性分桶键；
- 顶点删除级联删除所有相邻边；
- 边更新支持端点、权重、层级变化，必要时迁移源分片贡献；
- 每次成功操作递增工程版本与提交序号。

重划分流程：

1. 校验新分片全集；
2. 清除旧的实体绑定并重新求解归属；
3. 找出区间/ID 发生变化的旧分片与新分片；
4. 移除受影响旧分片的全部贡献；
5. 并行构建受影响新分片索引；
6. 按 key 并集递增全局版本；
7. 受影响分片索引版本整体替换；
8. 依赖旧/新分片或变更实体的缓存整批失效。

演示在每次编辑后执行全量重建，并逐查询比较访问序列、访问边、结果、路径与缓存 ID；同时比较索引键集合、引用集合与实体集合（不把初始版本肯定不同的全量重建版本号当作结果一致性）。

## 7. 并发与预算

- `Workers` 必须在 `1..32`；否则 `E_THREAD_BUDGET`。
- `BufferPerWorker` 必须 >0；构建单分片时唯一 key 贡献超过上限即 `E_BUFFER_BUDGET`。
- 遍历中访问顶点、边、索引探针和依赖的工作集超过缓冲上限也返回 `E_BUFFER_BUDGET`。
- 分片索引构建、重划分构建、查询求值都走有界 worker 池。
- 所有结果先写入按 shard/query 索引定位的槽位，再在固定顺序提交，因此调度顺序不改变键集合、序列或缓存编号。
- `Micros` 和 worker ID 仅用于诊断，不参与任何断言或正确性分支。

## 8. SQLite 提交与恢复

数据库使用 WAL、`synchronous=FULL`。每次提交在单个事务中：

1. 删除并写入 `shard_index`；
2. 删除并写入 `index_key`；
3. 删除并写入 `cache_entry`；
4. 写入 `commit_log`；
5. 最后写入包含 `commit_seq` 的 `meta`；
6. 提交事务。

事务使这组顺序对读者原子可见。注入失败点位于各阶段之后、事务提交之前；返回错误会回滚，旧检查点保持完整。

恢复：

1. `PRAGMA quick_check`；
2. 校验格式版本、工程 ID、工程版本；
3. 校验工程快照 digest；
4. 校验提交日志与 header 一致；
5. 校验分片贡献引用的 key 存在；
6. 直接恢复索引层与缓存层，不重建旧索引。

任何版本不匹配都返回 `E_CHECKPOINT_VERSION_MISMATCH`，调用方只能从当前工程全量重建，不得复用旧索引。截断/损坏文件映射到 `E_CHECKPOINT_TRUNCATED` / `E_CHECKPOINT_CORRUPT`。

## 9. 确定性来源

样本生成器使用自实现 LCG，固定种子产物字节稳定；参考真值走独立的键生成、BFS、操作模拟与缓存依赖收集实现，不复用运行时求值函数。

所有 map 在参与可观察输出前排序：

- 分片按 ID；
- 顶点/边按声明序号+ID；
- 标签/层级/属性规则排序；
- 索引键、引用分片、实体、查询、缓存 ID 排序；
- JSON 由 Go encoder 对 map key 排序。

因此相同输入在 worker、布局、分片调度或提交批次变化下具有相同的索引键集合、访问序列、结果和缓存 ID。
