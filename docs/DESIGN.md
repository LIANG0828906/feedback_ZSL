# 管线设计

## 模块边界

- `archive.cpp`：三版格式解析、统一模型校验、升级与降级损失检查。
- `visibility.cpp`：视锥平面、软件离屏深度图、HZB、边界一致性、不可变快照。
- `pipeline.cpp`：单任务锁、优先级队列、并行加载、取消、确定性发布。
- `recovery.cpp`：逐分块临时文件、原子重命名、哈希链和恢复扫描。
- `compare.cpp`：统一场景坐标下的多版本掩码对比与原因归因。
- `generator.cpp`：确定性 3x3 场景、三版样本和基线哈希。
- `tools/chunkpipe.cpp`：生成、运行、恢复、对比、确定性检查和导出示例界面。

## 不可变统一模型

每个分块使用 `std::optional` 区分“字段明确不存在”和“字段有值”。旧版没有的
遮挡体、网格、压缩和层级字段不会被补成默认值。优先级是管线必需调度信息，
因此旧版按公开规则推导，并用 `PrioritySource` 永久标注来源；写回 v3 时该来源
也会被保存。

## 流式调度

1. 从分块集合中排除已发布或已恢复的分块，剩余候选去重。
2. 按优先级、视点距离、分块 ID 排序。
3. 多个工作线程并行加载分块；每个任务完成后在加载检查点响应取消。
4. 成功结果按分块 ID 排序后提交恢复快照，并合入候选已加载集合。
5. 候选集合整体完成剔除后，才构造新快照；任何失败、取消或边界错误都不会
   修改已发布快照。

失败分块产生 `E_LOAD_FAILED` 位置，不会生成占位几何，也不会出现在已加载集合
或可见记录中。快照中其掩码字节保持 `0`。

## 剔除与离屏深度金字塔

1. 使用透视矩阵构造六个视锥平面；AABB 完全位于任一平面外时视锥剔除。
2. 所有已加载且显式标记为遮挡体的三角形被光栅化到 `256x144` 软件深度图。
3. 深度图逐级取 `2x2` 最小值生成 HZB。
4. 候选分块投影八个 AABB 角点和中心，按投影尺寸选择 mip，比较候选深度与
   该区域最小深度。
5. 无样本通过则遮挡剔除；部分样本通过则进入临界分块列表。

掩码 bit：

| bit | 含义 |
| ---: | --- |
| 0 | 已加载 |
| 1 | 位于视锥内 |
| 2 | 可见 |
| 3 | 临界 |
| 4 | 显式遮挡体 |

相邻 AABB 接触面按 5x5 点采样两侧内缩条带，计算可见比例。比例差超过存档声明
容差时返回 `E_VISIBILITY_MISMATCH`，位置包含两个分块、边界段、两侧比例和容差，
不会用任一侧结果覆盖另一侧。

## 版本化发布

`FrameSnapshot` 构造完成后不再修改，以 `shared_ptr<const FrameSnapshot>` 保存。
发布时在互斥锁内整体替换指针；查询先取得该指针，再在锁外读取，因此一次查询
看到的已加载集合、掩码、统计和边界样本都属于同一版本。内容哈希使用确定性
FNV-1a 64 位组合，不是安全密码学哈希。查询携带期望版本和哈希，不匹配返回
`E_VERSION_STALE`。

## 恢复协议

快照文件名为 `00000001-c00000004.snap` 形式，正文包含：

- 快照格式版本、序号、场景 ID、存档版本和分块 ID；
- 前序链哈希、内容哈希和调度状态；
- AABB、顶点、索引、优先级及来源、网格、遮挡体、压缩和层级字段；
- 正文末尾链哈希。

写入顺序：创建 `*.tmp`、完整写入并关闭、`rename` 到正式文件名。恢复只扫描
正式 `.snap`，残留临时文件被忽略。恢复按序号检查连续性、前序链、正文链、
场景身份和快照内容与当前存档分块的内容哈希。首个异常即返回
`E_RECOVERY_INVALID`。已提交分块注入管线后不再进入加载队列，提交函数对重复
分块返回 `skipped`。

强制终止只保证最后一次成功原子提交之前的快照完整；不承诺生成退出报告。

## 并发与取消

每个 `Pipeline` 使用原子 `busy` 标志保证同一场景最多一个流式剔除任务，重复
提交返回 `E_BUSY`。取消检查位于：

- 工作线程取出新分块前；
- 分块加载完成并准备记录结果时；
- 每个分块剔除开始前；
- 每个边界检查开始前。

取消或异常时，本轮候选网格只存在于局部容器，函数返回后释放；发布指针保持
最后一次成功版本。

## 多版本对比与归因

比较前校验所有存档 `scene_id` 一致，按统一世界坐标和分块 ID 对齐。差异原因：

- `load_order`：两侧加载集合不同，通常来自部分流式加载或不同优先级顺序。
- `format_degradation`：遮挡体、网格、压缩、层级或边界等格式能力不同。
- `priority_derivation`：优先级值或来源不同但可见集合相同。

`diff_report.json` 同时输出 `differences`（可见掩码不同）和
`metadata_differences`（掩码相同但影响后续调度的属性不同），均定位到分块和
字段，不只给总体统计。

## 确定性

- 格式、哈希、队列排序、边界采样和发布顺序均不依赖线程完成顺序。
- 软件光栅器固定采样点、固定浮点运算顺序和固定图像尺寸。
- 连续两次渲染比较完整掩码字节、`CullStats` 内存布局和快照内容哈希。

## 渲染后端

当前深度金字塔由确定性软件离屏帧缓冲生成，以避免 GPU 驱动差异破坏逐字节
验收。该实现的接口边界是 `renderVisibility` 内部的遮挡深度图生成；替换为
OpenGL 4.1 FBO 适配层时，调度、发布、恢复、错误码和多版本比较逻辑无需变化。
