# 关卡音频环境声遮蔽与混响区域编辑工作台 — 技术说明

## 1. 范围与约束

本工作台面向平面游戏关卡的声学设计，处理混响区域、声源、听者路径点与墙体遮挡，
输出逐声源-听者对的遮挡判定、绕射长度、衰减曲线、声压级，以及逐听者路径点的声学剖面。

- 纯 Go 实现，SQLite 采用纯 Go 驱动 `modernc.org/sqlite v1.34.4`，`CGO_ENABLED=0` 可构建，无本机链接库。
- 样本由固定种子（`generator.Seed = 20261124`）确定性生成，不访问网络、音频设备或外部素材。
- 几何判定使用声明定点精度（默认 4 位小数，合法区间 `[1,8]`），声学曲线使用 IEEE-754 float64 确定性合成。

## 3. 关键设计

### 3.1 定点几何

- 坐标经 `Converter.FromFloat` 量化为 `int64` 定点数，标度 `scale = 10^scaleBits`。
- 线段求交使用 128 位有符号叉积方向判定，避免 `int64` 乘法溢出；不依赖浮点符号。
- 墙体在引擎内按 ID 排序后参与判定，`BlockingWalls` 返回排序后的墙体 ID 列表，
  因此同一几何无论输入顺序如何，遮挡集合与绕射长度完全一致。
- 绕射采用单折点墙角折线 `S -> 墙角 -> L`：仅豁免折线贴附的宿主墙，
  其余墙体仍参与阻断；无可行折线时返回 `E_PATH`。

### 3.2 声学合成

- 衰减率 `rate = 60 / RT60`（dB/s），曲线 16 个采样点、步长 0.05s，
  `curve[k] = 20*log10(gain) - rate * t_k`。
- 声压级 `SPL = 90 - 20*log2(max(effectiveLen,1)) + curve[0] - 遮挡惩罚(18dB)`。
- 合成输入只包含区域参数、有效长度与遮挡布尔值，与线程标识、缓存命中状态无关，
  因而并行/缓存复用不改变逐采样结果。

### 3.3 依赖与精确失效

依赖关系显式建模：

```
区域(参数/几何版本) -> 声源 -> 声源听者对 -> 听者剖面
墙体集合           -> 全部声源听者对
```

- 编辑区域参数：仅失效引用该区域的对及其下游听者剖面，未受影响区域全部复用缓存。
- 拖动区域边界：提升 `geomVersion` 并走同一区域级失效路径。
- 每次失效输出含对象标识、类型与原因的清单，不做整关卡重建。
- 单对输入哈希（区域+声源+听者+墙体+定点位数+算法版本）作为缓存键，
  哈希未变即命中内存或 SQLite 持久化缓存。

### 3.4 三路径一致性

1. 实时编辑（增量）：命中缓存的对直接复用，未命中对在线程池并行重算。
2. 断点恢复：重开 SQLite，校验快照元数据后从持久化缓存恢复。
3. 一次性全量：从空缓存重算全部对。

三条路径对同一工程与编辑序列产出位级一致的曲线与剖面；`internal/compare`
在发现差异时返回 `E_DIFF`，定位首个不一致的声源听者编号、曲线采样序号与字段名，
并写明两侧实测值。

### 3.5 检查点与资源边界

- 按听者 `windowId` 分窗口，每个窗口在单事务内原子提交窗口摘要与该窗口全部对结果。
- SQLite 连接 `SetMaxOpenConns(1)`，写入严格串行、窗口按 ID 升序，杜绝交错。
- 快照元数据记录工程内容哈希、算法版本、定点位数与区域参数/几何版本；
  重启时任一不匹配则整体作废快照并全量重算，禁止混用旧窗口。
- 线程池容量 = `MaxWorkers * PerWorkerBuffer`，缓冲耗尽时提交方阻塞排队，
  并通过背压事件记录原因，绝不静默丢弃任务。

## 4. 错误码

| 错误码 | 触发条件 |
| --- | --- |
| `E_SCHEMA` | 字段缺失、多边形不闭合/自交、端点非有限、坐标越界、真值声明缺失 |
| `E_REF` | 声源/听者引用不存在的区域，错误中携带对象标识 |
| `E_GEO` | 定点 `scaleBits` 越界（不在 `[1,8]`），指出字段 `scaleBits` |
| `E_DEGEN` | 墙体两端点退化重合 |
| `E_PATH` | 被遮挡对不存在可行绕射折线路径 |
| `E_DIFF` | 增量/恢复与全量结果逐采样不一致，携带定位与两侧实测值 |
| `E_STORAGE` | SQLite 持久化故障 |

单对计算的异常被收敛进 `Result.Failed/ErrorCode/ErrorDetail`，不污染其他对，
工作台提供逐对重试。

## 5. 运行方式（Windows 本地命令行）

```bat
go mod download
go build ./...
go test ./...

REM 生成确定性样本（data\project.sample.json）
go run ./cmd/workbench -stage generate

REM 三路径一致性 + 真值核对 + 断点恢复，报告落盘 artifacts\runs
go run ./cmd/workbench -stage verify

REM 启动交互式工作台
go run ./cmd/workbench -stage serve -addr 127.0.0.1:8080
```

纯 Go 无 CGO 构建：

```bat
set CGO_ENABLED=0
go build ./...
```

## 6. 验证结果

在随仓库的固定种子样本（2 区域、6 声源、8 听者、7 墙体、48 声源听者对）上：

- 48 对全部完成计算，其中 11 对被遮挡且均有可达绕射，0 对失败。
- 遮挡布尔、绕射长度、衰减曲线与声压级与解析真值在声明容差内全部吻合。
- 区域参数编辑后仅 24 个 R2 相关对重算，24 个 R1 对全部缓存命中。
- 增量路径、断点恢复路径与从空缓存全量重算逐采样一致（`threePathEqual=true`）。
- 4 个检查点窗口按序原子写入，重启后兼容快照成功恢复（`recovery=ok`），
  版本/哈希不匹配时快照整体作废。
- `go test -race` 在线程池、编排器与引擎包上无数据竞争。
