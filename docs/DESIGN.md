# 设计与一致性说明

## 1. 确定性边界

### 样本

生成器仅使用固定 seed 和 `math/rand` 的固定序列。每张样本包含：

- 线性渐变背景
- 高对比矩形色块
- 与局部背景颜色接近的低对比椭圆目标
- 中等对比圆形目标
- 固定随机噪声像素

真值掩码由解析形状栅格化得到，区域重心、面积和外接框直接从像素级真值掩码计算。清单保存图像哈希、各区域掩码哈希、汇总掩码哈希和真值指纹。

### 区域生长

对每个种子：

1. 计算 RGB 欧氏颜色距离。
2. 计算亮度 Sobel 梯度。
3. 阈值化候选图：`color_distance <= color_tolerance && gradient <= gradient_threshold`。
4. 从种子执行固定四邻域顺序的 BFS。
5. 对生长掩码执行结构元素为方形、零边界的开运算后闭运算。
6. 选择与种子相关的最稳定连通块，拒绝触边、面积超限或越出真值范围的外溢。

种子在参数快照中按 `(y,x)` 规范化排序，区域编号与统计序列因此不依赖调用方传入种子的顺序。算法不使用 map 遍历顺序、线程 ID、时间或随机数决定像素归属。

## 2. 预览与精确重算

预览只读取版本库最新快照一次，记录：

- `param_version` / `params_hash`
- `downsample_factor`（当前为 1）
- BFS `iteration_budget`
- 各区域初始/最终迭代数
- 是否因预算截断而回退完整分辨率
- 延迟实测值与清单上限

预览先使用受限 BFS 预算。若任一区域在预算内未完成生长，则在同一个不可变快照、同一种子、同一后处理链上完成全分辨率生长，避免把截断结果静默当作最终结果。该行为通过 `fallback_full` 明确记录。

停止交互后，精确任务在启动时通过版本号取得并锁定快照。预览和精确结果使用清单声明的容差比较：

- 区域数量绝对差
- 每个区域重心欧氏距离
- 每个区域面积相对误差

超限返回 `E_DIVERGE`，details 包含三项实测值、容差、首个不一致区域编号和首个差异像素坐标。

## 3. 参数版本与提交边界

每次参数更新都生成新版本，即使参数值相同也不会复用旧版本号。快照包含：

- 颜色容差
- 梯度阈值
- 结构元素尺寸
- 规范化种子点
- 参数哈希
- 算法版本

精确会话将完整参数 JSON、参数哈希、版本号、算法版本和样本指纹写入 SQLite 会话元数据。已提交阶段不可改写；相同内容哈希的重复提交是幂等的，不同内容会被拒绝。跨会话版本混用返回 `E_VER`，details 同时给出 `left_version` 和 `right_version`。

## 4. SQLite 检查点

表结构：

- `sessions`：样本/图像/真值指纹、完整参数快照、算法版本、尺寸、块网格、最终结果哈希
- `tile_stages`：每块 `growth` / `cleanup` / `stats` 的状态、输出、内容哈希、版本
- `commits`：规范提交序列与提交记录

阶段状态迁移：

```text
pending -> in_progress -> committed
                       -> failed -> in_progress -> ...
```

其他迁移返回 `E_STATE`，状态保持不变。提交事务一次写入输出、内容哈希、参数版本、算法版本和提交记录。

提交序号不是按实际完成顺序自增，而是预留规范槽位：

```text
seq = tile_index * 3 + stage_index
```

因此某块失败时，其他块仍可完成并提交；重试失败块时填入原槽位。最终按 `seq` 查询仍得到稳定的块序阶段序列，不依赖线程调度。

启动或恢复时，只要发现以下任一不一致，整个会话作废并全量重算：

- 样本 ID、图像哈希、真值指纹、尺寸、块尺寸或网格
- 参数版本、参数哈希、完整参数快照或算法版本
- 缺失/重复阶段行
- 已提交阶段输出内容哈希
- 提交序号与规范槽位
- 提交引用非已提交阶段

进程中断留下的 `in_progress` 阶段在恢复时转为 `failed`，随后允许合法重试。

## 5. 并行与资源边界

分块按波次执行，每波最多 `MaxParallel` 块。每波结果进入容量为 `PerBlockBuffer` 的通道，通道满时生产者阻塞，不丢块。每块每个阶段的输出受 `MaxStageBytes` 限制；超限只将该块阶段置为失败并返回 `E_BLOCK`。

提交由主协程按块序执行，所有 SQLite 写入由存储层互斥锁和单连接串行化。单个块失败不会篡改已提交块；其他块继续推进，失败块后续阶段保持未提交，等待恢复。

## 6. 三条执行路径

验收覆盖：

- 实时增量：新会话从零按块提交
- 断点恢复：提交若干阶段后暂停，再用 `resume` 继续
- 一次性全量：删除旧会话后从零重算

三条路径对同一图像、同一参数快照输出：

- 逐像素相同标签掩码
- 相同掩码哈希
- 相同区域统计
- 相同 72 条阶段提交序列（24 块 × 3 阶段）

## 7. 独立验证器

`verify` 不运行区域生长，也不读取样本图像或真值掩码像素。它只读取：

- `sample_manifest.json` 中的真值指纹和布局声明
- SQLite 会话元数据
- 已持久化的每块三阶段输出与哈希
- 规范提交记录

验证器重组 growth/cleanup 掩码，从 cleanup 块重算局部统计并聚合，与 stats 阶段产物、最终掩码哈希和统计哈希交叉校验。任何不一致均报告 `x`、`y`、`tile`、`stage`。
