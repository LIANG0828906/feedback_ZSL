# 设计与确定性协议

## 1. 切分与唯一所有权

1. 每个面片取三个顶点的空间单元包围盒。
2. 包围盒触及多个单元时，面片唯一归入字典序最小的单元，并写入 `straddling_faces`。
3. 有面片的单元按 `(x,y,z)` 排序后分配连续块 ID。
4. 分块内容哈希只覆盖输入内容、分块尺寸、面片/顶点归属和 straddle 记录，因此同一输入与分块尺寸在不同并行度下得到相同 `table_hash` 和 `boundary_hash`。

## 2. 边界映射

对全局无向边收集引用面片的分块所有者。只要一条边的面片跨越多个块，就为每个有序块对 `(a,b), a<b` 记录：

- 块编号；
- 相邻块编号；
- 稳定边界顶点 ID（原始全局 ID，焊接代表元保持在该集合内）；
- 边界边端点；
- pair 规范哈希。

`boundary_map.json` 是该映射的确定性可读输出。跨块修复只能读取这份映射；`evaluateHoleBoundaryGates` 会在两端映射未提交时返回 `E_BOUNDARY_PENDING`，并附孔洞 ID 与所有者块。

## 3. 修复流水线

全局规划只使用输入、配置和已提交 plan，结果与线程调度无关：

1. **焊接**：在块内以及已提交边界的双端候选集合上，以容差网格做确定性并查集；代表元取组内最小原始 ID。
2. **碎片删除**：按任意共享边做面片连通分量；小于 `min_component_faces` 的分量删除，避免把非流形 fin 误判为孤立碎片。
3. **孔洞提取**：仅使用全局引用数为 1 的边，沿闭合边界环遍历。输出环顶点数、包围盒、涉及块和稳定孔洞 ID。
4. **孔洞填补**：孔洞所有者是涉及块中最小块 ID；投影后耳切，失败时确定性扇形回退。新三角形加入同一邻接结构。
5. **重复填补拦截**：已在原网格或其他填补中的规范无序三角形再次出现时返回 `E_TOPOLOGY_CONFLICT`，定位块与 `hole_id`。
6. **非流形边拆分**：对引用数大于 2 的边，依据除该边外的共享邻边做连通面组；最低组保留原顶点，其他组分配规范顺序的新稳定 ID。每组记录唯一所有者块。
7. **输出构建**：原始面、拆分面和填补面按块 ID 与规范键排序，写入分块 bundle。

## 4. 调度与预算

- 配置加载后只读，运行时不提高 `parallelism`、`memory_budget_bytes` 或 `block_memory_bytes`。
- 提交序号等于块 ID。可运行任务按序号分批。
- 单块预估超过 `block_memory_bytes` 时在任何块任务启动前返回 `E_BUDGET_EXCEEDED`，并携带 `chunk` 与 `estimated_bytes`。
- 一批任务累计预估不超过全局预算；后续任务进入等待队列，等当前批次释放后继续。
- `trace.log` 为每个块记录 `estimate`、`WAIT_QUEUE`/`COMMITTED`、bundle hash 和链前驱。

## 5. 原子提交与恢复

每个 `.mrchunk` 是完整结果、统计、局部边界哈希和链前驱的单一序列化文件。写入顺序：

1. 同目录唯一临时文件；
2. 写完并 `fsync`；
3. 原子 `rename` 到正式路径；
4. 父目录 `fsync`（POSIX）。

已存在正式 bundle 绝不覆盖；若内容哈希不同则返回 `E_RECOVERY_INVALID`。恢复时按块 ID 验证 plan、版本、内容哈希、局部边界哈希和链式哈希，然后只重建缺失块。强制终止后的轨迹文件也会根据同一已提交集合重新规范生成。

## 6. 拼接与校验

拼接按块 ID 合并：

- 同一稳定顶点 ID 必须具有相同坐标；
- 面片引用的每个顶点必须存在于至少一个已提交块；
- 每个跨块边界边必须恰好被两个面片引用；
- 规范三角形重复的填补面片被拒绝；
- 最终 mesh 使用排序后的顶点和规范面片顺序编码，因此与块执行/完成顺序无关。

报告同时给出焊接前后顶点数、填补面片数、拆分边/组/复制顶点数、删除碎片数、法向平均/最大偏差，以及超容差时的块和原始面片定位。

## 7. 渲染隔离

后台线程调用 `repairMesh`。每次分块原子提交后，引擎构造一个完全独立的 `shared_ptr<const Snapshot>`，其中包含网格、每面片块 ID、已提交块列表和内容哈希，然后整体替换 UI 持有的指针。GLFW/OpenGL 主线程只在锁内复制该共享指针，不读取任何正在构建的临时网格，也不会观察到半个分块。

按下 Esc 设置协作式取消标志；引擎在当前分块批次结束或下一次提交前返回 `E_CANCELLED`，RAII 释放锁、文件句柄和缓冲。

## 8. 并发会话

锁文件键为输入网格的规范 SHA-256，放在配置的 `temp_dir`。POSIX 使用 `flock(LOCK_EX|LOCK_NB)`，进程被强杀时内核自动释放；第二个会话返回 `E_BUSY`。
