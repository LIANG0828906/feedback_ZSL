# 设计与技术说明

## 1. 数据模型

数据集由 `diffrender.generator` 在固定种子下生成。每个 group 包含：

- `scene.json`：扰动后的初始场景、相机、渲染参数。
- `targets.json`：目标图像清单和解析真值。
- `images/*.npy`：float64 目标图像。

场景中的几何体如下：

- 球体：中心、半径、RGB 反照率。
- 无限平面：平面上一点、单位法线、RGB 反照率。
- 矩形光源：中心、法线、两个半轴尺寸、标量强度。

相机使用 3x3 内参 `K` 和 4x4 world-to-camera 外参。加载时验证：

- 所有数值有限。
- 内参非奇异。
- 外参旋转非奇异，底行严格为 `[0, 0, 0, 1]`。
- 球半径、平面/光源法线、光源半尺寸、反照率和强度范围合法。
- 目标清单引用的相机存在，尺寸为正。
- 解析真值标签与场景优化参数完全一致。

任何结构问题返回 `E_SCHEMA`，`field_path` 例如 `cameras[0].intrinsics`、`geometries[1].radius`。

## 2. 可微渲染

每个像素生成世界空间射线：

\[
\mathbf{o} = -R^T \mathbf{t}, \qquad
\mathbf{d} = R^T K^{-1}[u, v, 1]^T
\]

球求交使用二次方程。有效判别式下取最近正根；平面求交使用分母阈值和射程阈值。所有几何体的候选 `t` 拼接后取最小索引，得到最近交点、法线和反照率。

直接光照：

\[
L(\mathbf{x}, \omega_o) =
\rho \left(a + \sum_l I_l \frac{1}{N}\sum_{n=1}^{N}
V_{l,n}(\mathbf{x}) \max(\mathbf{n}\cdot\omega_{l,n},0)
\frac{1}{d_{l,n}^2 + 0.2}\right)
\]

- `a` 是场景环境光。
- `I_l` 是可优化光源强度。
- 矩形光源采样使用固定 Halton 序列加种子偏移。
- 对每个球体计算遮挡射线求交，并用 sigmoid 软化遮挡边界，形成可微软阴影近似。
- 平面只作为接收面，不作为阴影遮挡体，避免自交把整片地面压黑。

生成器在解析真值处调用同一前向函数产生目标图像，因此精确模式在真值处与目标图像逐元素相等。

## 3. 参数化与梯度

所有优化变量放在一个扁平 float64 `torch.nn.Parameter` 中：

- 球心：直接参数。
- 半径：`softplus(raw)`。
- 反照率：`sigmoid(raw)`。
- 光源强度：`softplus(raw)`。

这样保证半径、反照率、强度在全优化过程中保持合法范围。每个标量有稳定标签，例如：

```text
sphere_0.center.x
sphere_0.radius
sphere_0.albedo.r
key_light.intensity
```

损失为全部目标图像上的均方光度误差。分块模式下每块损失为：

\[
\frac{\sum_{(x,y)\in block} \|\hat I(x,y)-I(x,y)\|_2^2}
{\sum_{\text{all images}} H W 3}
\]

块损失在固定块序中相加，梯度也按固定块序累加。

## 4. 模式选择

`strategy.py` 使用物体数、图像数、分辨率、优化轮数和内存预算估计工作集：

```text
per_pixel = max(8, 4 * object_count + 3 * shadow_samples + 8)
full_working = total_pixels * per_pixel
tile_working = tile_pixels * per_pixel * parallel_blocks
```

执行规则：

1. 当整图工作集不超过内存预算的 65%，像素数不超过 `max_exact_pixels`，迭代数不超过 `max_exact_iterations` 时选 `exact`。
2. 整图超预算但固定块可放入预算时，若迭代数不超过降采样阈值则选 `tiled`。
3. 长迭代预算下重复分块边界开销不划算，选 `downsample`，寻找使低分辨率工作集落入预算的最小 2 的幂倍率。
4. 内存极其紧张且分块仍可容纳时优先保留分辨率，自动缩小块尺寸。

决策输出实际模式、倍率、块尺寸、并行数、缓冲上限、估计工作集和自然语言解释。`mode-compare` 对 1x/2x/4x/8x/16x 输出 MAE、RMSE、`max_abs` 和单调性。聚合 MAE/RMSE 是信息损失验收指标。

## 5. 梯度防护

每轮步骤：

1. 收集标量梯度并应用可选测试注入。
2. 检测非有限梯度。
3. 统计逐参数梯度范数。
4. 连续超阈值计数；超阈值标量在本轮临时标记为 suspect，不参与更新和全局裁剪。
5. 达到耐心值后永久冻结该标量；任何 suspect/冻结标量梯度置零。
6. 若启用裁剪，仅对剩余梯度做全局范数裁剪。
7. Adam 步进。
8. 对 suspect/冻结标量恢复步进前数值，消除 Adam 动量造成的隐式更新。

前两轮连续超阈值时，故障标量保持原值，其他参数不受该异常值造成的裁剪缩放污染；达到耐心值后产生 `E_GRAD`，其他参数已在同轮完成合法更新。记录每轮全局裁剪前范数、实际应用范数、裁剪触发、逐参数范数、suspect 和冻结列表。

裁剪配置（开关、阈值、爆炸阈值、耐心）进入配置指纹和检查点。

## 6. 分块状态机

块由 `(round, sequence, image, x, y, width, height)` 标识，固定大小由策略决定。`BlockLedger` 要求：

- 每轮从连续 `0..N-1` 的块序列开始。
- 成功提交必须等于当前期望序号。
- 块 ID 和阴影种子的固定快照。
- 快照哈希和参数版本与轮开始一致。
- 重复提交或漂移快照返回 `E_STATE`，不改变账本。

调度器为每块保留预算单元。若下一块会超过缓冲上限，调度器等待最早块完成并提交，再释放预算；不会静默丢弃。块使用独立参数快照 leaf 张量，前向/反向异常只产生本地失败记录，不合并其梯度。失败块立即允许重试；重试成功后按原序号提交。

## 7. 检查点

检查点目录包含：

- `checkpoint.json`
- `.checkpoint.lock`

写入流程有跨平台进程锁，先在同目录写临时文件，`flush + fsync`，再 `os.replace`，最后同步目录。JSON 包含：

- 原始参数、Adam 状态。
- 梯度守卫状态和历史。
- 完整块账本与每块梯度缓冲。
- 损失历史、策略和配置。
- 数据集内容指纹。
- `checkpoint_format`、`algorithm_version`、`parameter_version`。
- `config_fingerprint`，其中含裁剪配置。
- 对除 `content_hash` 外全部内容的 SHA-256。

加载时先重算内容哈希，再比较格式、算法、配置和数据集版本。任一不匹配就返回完整快照无效，调用方从初始场景全量重算，禁止只复用部分状态。

## 8. 三路径一致性

三条路径共享同一 `OptimizationRunner` 状态机：

- 实时：连续运行，在窗口边界保存。
- 断点恢复：运行到窗口边界，销毁 runner，新建 runner 加载快照后继续。
- 一次性：关闭检查点，连续运行。

检查点只持久化状态，不改变数学步进。给定固定 CPU 线程设置、参数布局、块序、种子、Adam 状态和学习率日程，三条路径应逐元素一致。`compare.py` 按参数、损失轮次、块提交、标量字段和可选梯度历史定位首个差异；不一致抛 `E_DIFF`。

## 9. 诊断与异常

诊断导出：

- 每张目标、重建和绝对差异热力图。
- 光度损失曲线。
- 全局梯度范数和裁剪触发点。
- 块级平均耗时。
- 参数真值表、绝对误差和相对误差 CSV/JSON。

目标图像不可读/损坏/尺寸不符为 `E_DECODE`。单个块前向/反向异常为失败记录并可重试；重试耗尽为 `E_BLOCK`。非法提交为 `E_STATE` 且账本保持原状。
