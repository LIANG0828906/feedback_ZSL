# 字幕排版管线设计说明

## 1. 模块划分

| 模块 | 职责 |
| --- | --- |
| `samples.py` | 固定种子生成确定性媒体工程（波形、清单、呈现参数） |
| `loader.py` | 工程加载与结构校验（E_SCHEMA/E_REF/E_WIN/E_DECODE） |
| `envelope.py` | 逐帧 RMS 能量与语音段起止检测 |
| `wrapping.py` | 最小代价 DP 折行、标点不孤立、多屏切分与字符守恒 |
| `timing.py` | 可读时长模型、空隙延展、三手段取舍、E_GAP/E_TIMING |
| `states.py` | 台词四态状态机与提交边界 |
| `checkpoint.py` | 原子串行检查点、版本门控恢复 |
| `pipeline.py` | 线程池调度、缓冲预算、按时间轴顺序串行提交 |
| `validator.py` | 仅依赖持久化结果与清单的独立验证器 |
| `truth.py` | 解析真值生成 |
| `diagnostics.py` | 无界面诊断报告（Tk 面板为可选） |

## 2. 时间维度

帧长 `frame_length`、帧移 `frame_shift` 在清单中声明。检测先取能量高于
`energy_threshold` 的置信语音帧，再按帧长/帧移关系把内缩的置信区间还原为
帧网格上的精确段边界；背靠背段之间的零标记连接点按能量凹陷切分。

每句台词的基础窗口为其显式窗口，否则为所属语音段。需要更长可见时间时，
窗口向两侧静音空隙对称延展，相邻段按空隙各占一半的上限延展，因此数学上
保证互不重叠。

### 可读时长模型

```
read_time  = 总字符数 / 阅读速度上限
dwell      = (min_line_dwell + line_dwell * 单屏最大行数) * 留白系数
screen_gap = screen_gap_s * (屏数 - 1)
required   = read_time + dwell + screen_gap
```

## 3. 三手段取舍与错误边界

优先级由 `tradeoff_priority` 配置，默认：

1. `compress_margin`：留白系数 1.0 -> 0.5，压缩行驻留；
2. `reclaim_gap`：继续回收相邻静音空隙延展窗口；
3. `add_screens`：增加屏幕，降低单屏最大行数从而降低 dwell。

每次取舍都落一条含台词编号、手段、理由、取舍前后所需时长的记录。

- 阶段 A 后仍缺时长且**完全没有可延展空隙** -> `E_GAP`，附冲突台词编号；
- 穷尽三手段后窗口仍短于最终版面最短可读时长 -> `E_TIMING`，附实测/所需。

## 4. 版面维度

折行是对“原子”（CJK 单字、标点、连续 ASCII 词）的最小代价 DP，代价由
留白参差权重与断点权重组成；任何会让标点出现在行首的断点被禁止。单原子
宽度超过行宽即 `E_PARA`。多屏切分按单屏行数上限做确定性装箱，并在重排
后校验重组文本与原文严格相等（不丢字、不重字）。

## 5. 并行与确定性

工作线程池受 `max_workers` 与每线程文本/采样缓冲信号量约束；预算耗尽时
任务在信号量上阻塞排队，不丢弃台词。每个台词的排布是纯函数，工作线程只
产出结果，提交由主线程按 `subtitle_id`（时间轴顺序）串行执行，因此串行、
并行产出逐句窗口、逐行折行与提交序列完全一致。

## 6. 检查点与恢复

每次提交在 `RLock` 内以临时文件 + `os.replace` 原子写入，记录含结果、
工程内容哈希、参数哈希与算法版本。恢复时任一哈希或版本不匹配，则整个
快照作废并全量重排，禁止混用旧结果。强制终止后只能恢复已持久化且版本
匹配的台词，不会凭空生成完整时间轴。

## 7. 独立验证器

验证器不导入主链路内存状态，只读取持久化记录与清单，重新校验窗口不重叠、
不超阅读速度、折行行数/每行字符数与真值一致、总占用时长在容差内，并比对
取舍记录。返回首个违规的台词编号、违规项与实测值；损坏样本返回 E_DECODE。
