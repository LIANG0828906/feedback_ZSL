# 调度领域组件与诊断工作台 — 技术说明

## 1. 范围与约束

- 仅使用 Go 标准库与仓库内文件，无第三方依赖、无容器、无外部服务。
- 全部样本由 `internal/gen` 的确定性 LCG（固定种子 `20261127`）生成，跨机器、跨进程结果一致。
- 持久化未引入 SQLite 驱动，按题目允许改用仓库内文件格式承担同等职责：
  数据文件 `fsync` + 目录 `fsync`，全局提交指针以原子 `rename` 最后落盘。

## 3. 三版本归一口径

- 字段命名：v1 `snake_case`、v2 `camelCase`、v3 `kebab-case`。
- 清单形状：v1/v3 扁平；v2 为 zone→rack→node 嵌套树，装载器展平后按节点 ID 重排，
  保证三版本节点/Pod 遍历次序完全一致。
- CPU：内部统一毫核。v1/v2 整核 ×1000；v3 支持 `1500m`、整/小多核与百分比/比例字符串，
  比例按参考容量 8000m 半升取整。生成器让 v3 比例在该参考下精确可表示（整核 → 12.5% 的倍数）。
- 内存：内部统一字节，接受 `Ki/Mi/Gi/Ti` 与裸字节。
- 权重：内部统一万分比 bps；v1 千分比 ×10（精确），v2/v3 原生 bps；范围 `[0,10000]`。
- 时刻：v1 tick（固定 100ms/tick）→ 毫秒，v2/v3 毫秒。
- 软超时：v3 省略该可选字段；为满足三版本结构完全一致，内部模型不承载该字段（归一为 0/false）。
- 拓扑键语义冲突：装载器以权威语义表校验，不一致返回 `E_TOPO_KEY_CONFLICT`，不猜测。

## 4. 可行性与淘汰（约束编号）

按声明次序分族收集、同时失败全部上报：

- `C1` 资源容量（CPU、内存，统一毫核/字节）
- `C2` 节点选择器
- `C3` 未容忍污点（逐污点给编号）
- `C4` 必须类亲和（同拓扑域至少一个匹配节点）
- `C5` 必须类反亲和（同域不得存在其它匹配节点）

可行集合与淘汰集合构成节点全集的一个划分。

## 5. 打分与两条路径

- 每条偏好规则输出分项：同域匹配数、同域上限、上限惩罚、bps 权重、原始贡献。
- 亲和贡献 `weight × min(matched, cap)`；反亲和贡献 `weight × max(cap-matched, 0)`。
- 原始总分用饱和 int64 累加；归一化将最大原始分映射到 10000 bps，半升取整，
  全部归一值落在 `[0,10000]`。选点按归一值降序、平局取 canonical 次序，结果确定。
- 路径选择依据 `候选节点数 × 偏好规则数`：`>40` 选 `TOPOLOGY_PREAGGREGATED`（先按
  规则×拓扑域预聚合计数，再 O(1) 取节点贡献），否则 `EXACT_NODEWISE`。两条路径使用
  同一套整数语义，分项与选点完全相同；耗时仅作诊断输出。

## 6. 定点换算与误差界

- 所有运算为 int64 定点，显式检测乘/加/比例溢出并饱和到 Max/Min；解析不使用浮点。
- 每次换算导出 `Trace`（操作、入参、结果、溢出/饱和标记），可逐项回放。
- 临界用例包含精确百分比、半毫核舍入、循环小数、核/毫核、千分比/万分比、内存、tick。
  逐项给出实际值、与真值绝对差、是否在声明容差内；非整数千分比显式拒绝而非截断。
- 排序核验：等比缩放分数后相对次序必须保持不变。

## 7. 增量失效

按逻辑顺序施加四类编辑：节点标签变更 → 拓扑域迁移 → Pod 需求调整 → 规则权重修改。
缓存键为 Pod×Node 内容指纹，只纳入真正影响该判定的输入（Pod 自身、候选节点、
同拓扑域相关节点）。每次编辑输出失效来源、受影响 Pod 集合与传播闭包（Pod|Node 对），
并统计复用/重算条目；最终与一次性全量重算逐 Pod 逐节点比对，要求零分歧。

## 8. 并行、背压与检查点

- 预算校验：并发 `1..64`、缓冲 `1..4096`，越界返回 `E_CONCURRENCY_BUDGET` /
  `E_BUFFER_BUDGET`。
- 真实并行 `Run` 用带权信号量硬限并发；确定性 `DeterministicRunner` 在信号量满时
  返回 `E_BACKPRESSURE`，背压可重复观测、绝不越界放行。
- 提交顺序：先写节点快照（含内容哈希）并 fsync，再写打分缓存并 fsync，最后原子更新
  `commit.json` 全局提交序号。任意提交点崩溃都不会读到指向未完成快照的缓存。
- 恢复仅接受魔数、状态版本、规则版本与节点快照哈希全部匹配的状态；
  校验和不符 → `E_CHECKPOINT_TRUNCATED`，版本不符 → `E_STATE_VERSION_MISMATCH`，
  版本不匹配时从起点整段重算。

## 9. 异常注入业务码

| 注入 | 业务码 |
| --- | --- |
| 权重刻度越界 | `E_WEIGHT_RANGE` |
| 资源需求为负 | `E_RESOURCE_NEGATIVE` |
| 拓扑键语义冲突 | `E_TOPO_KEY_CONFLICT` |
| 越界并发预算 | `E_CONCURRENCY_BUDGET` |
| 越界缓冲预算 | `E_BUFFER_BUDGET` |
| 预算耗尽背压 | `E_BACKPRESSURE` |
| 截断检查点 | `E_CHECKPOINT_TRUNCATED` |
| 快照版本不匹配 | `E_STATE_VERSION_MISMATCH` |

注入在输入深拷贝上进行，源工程 JSON 校验和保持不变；已提交打分结果在异常后仍可加载复用。
