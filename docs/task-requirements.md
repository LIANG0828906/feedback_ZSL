# 原任务说明

在一台没有历史代码的机器上，需要从零构建一套面向游戏与互动媒体音效素材的编解码质量评估管线与结果验证工具。本地确定性样本生成器按固定种子产出多条音频原始序列与对应的有损编码重建序列：原始序列由低频包络、高频纹理与嵌入的解析脉冲标记构成，重建序列由本地确定性的分帧频域编码器在可配置质量档位下生成，其量化误差分布由生成器解析构造；样本清单声明采样率、帧长、帧移、通道数、帧数与质量档位，并附带逐帧解析真值（若干脉冲标记的期望位置、逐帧期望信噪比与噪声基底残留标准差）。这些真值是观测与验收的唯一依据，不允许从缺失信息推断。管线需完成原始与重建两路序列的对齐、逐帧峰值信噪比与结构相似度评估、量化误差从变换系数经逆变换扩散到采样域的传播报告，并输出逐帧质量报告与差异热力图。业务方核心矛盾是并行调度与资源预算：评估分帧分块并行推进，但受工作线程数、每线程采样缓冲与任务队列预算限制，预算耗尽时只能阻塞排队而不能静默丢帧；同时要求实时处理、断点恢复处理与一次性全量重算三条路径逐样本与逐指标一致。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows 官方安装包），确认 go version 可执行，并设置本地模块缓存目录。
任务执行前初始化一个新 Go module，仅使用标准库与任务内自带的本地持久化实现，不引入外部数据库或网络依赖。
准备本地确定性样本生成步骤：由固定种子生成原始与重建音频序列、逐帧真值与质量档位清单，全部写入本地工作目录，不依赖真实音频文件或线上资源。
确认工作目录可写，用于写入持久化快照、差异热力图与逐帧质量报告；所有路径使用 Windows 本地路径。

业务要求：
1. 实现本地确定性样本生成器与序列加载校验：按清单声明的采样率、帧长、帧移、通道数、帧数与质量档位生成原始序列与重建序列，并将逐帧脉冲标记位置、期望信噪比与噪声基底残留标准差写入真值清单；加载时校验帧长与帧移为合规正整数、帧数与清单一致、质量档位在支持范围内、真值指纹完整，字段缺失或档位不支持返回 E_PARA，序列数据损坏返回 E_DECODE，并指出首个违规帧号或字段名。
2. 实现逐帧质量评估核心：按可配置评估窗口与滑步计算峰值信噪比与结构相似度，并在原始与重建序列上同时计算噪声基底残留标准差；指标计算须使用整型累加或声明精度的定点中间量并记录截断位置，全程统一为整型采样点时间单位，窗口尺寸与滑步越界返回 E_PARA 并指出字段名；同一序列与同一参数下逐帧评估结果须完全可重复，不随线程标识或完成顺序变化。
3. 实现量化误差传播建模与逐帧报告：逐帧记录变换系数量化前后误差、逆变换后采样域误差与相邻帧边界处的误差跃变，沿时间邻接关系报告误差扩散路径，并给出由量化步长、帧长与窗口尺寸推导的逐帧误差上界；上界只能由已观测的量化步长、帧长、帧移与真值中声明的噪声基底推导，不得读取真值中的期望指标反推；质量档位收紧时信噪比劣化方向必须单调可测。
4. 实现分帧分块状态机与提交边界：每帧按固定块划分，每块在每个评估阶段经历待处理、处理中、已提交、失败四类状态，只能沿合法迁移推进，进度以已提交块数与总块数表示；非法迁移返回 E_STATE 并保持原状态不变；已提交块的质量指标、误差统计与上界被冻结，后续参数调整只作用于未提交块，帧内块提交顺序稳定。
5. 实现分块边界精度一致性约束：结构相似度与噪声基底残留统计在块边界处须使用重叠边带并按确定性规则合并，边带宽度随评估窗口尺寸与滑步联动，保证分块并行评估结果与整帧单次评估结果在声明容差内吻合；边带不足返回 E_BAND 并给出块坐标与所需最小边带宽度，合并规则不得依赖块完成顺序。
6. 实现受限并行调度与资源预算控制：分块评估任务在工作线程池并行推进，须限制最大并行度、每线程采样缓冲上限与任务队列预算，预算耗尽时任务阻塞排队并记录排队原因与等待时长，不得静默丢弃或无序提交；共享检查点写入与块提交须串行化且保持块序稳定，并行运行与单线程串行运行对同一序列与参数须产出逐样本一致的指标与相同的块提交序列。
7. 实现可暂停可退出可重启续跑的持久化检查点：每提交一个块把该块的量化误差、重建采样摘要、质量指标、误差上界、输入内容哈希、参数版本与算法版本原子且串行写入本地持久化存储，写入不得交错；重启加载时若内容哈希、参数版本或算法版本任一不匹配须整体作废快照并全量重算，禁止部分混用旧块结果；用户取消或进程被强制终止后重启只能依据已持久化且版本匹配的块恢复，不得声称强制终止后仍能生成完整报告。
8. 实现三路径一致性与独立验证工具：实时处理、断点恢复处理与一次性全量重算对同一序列、同一质量档位与同一参数须产出逐帧相同的指标、相同的误差上界与相同的块提交序列，并提供自动比对定位首个不一致帧号、块坐标与字段名；独立验证工具仅从持久化的块结果与真值指纹出发重算逐帧指标、误差上界与边界合并结果，与主管线记录逐项比对后输出首个违规位置，且不得调用评估主路径。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本跑通压缩评估与三路径比对，并验证预算排队、异常码与分块边界合并结果一致。
